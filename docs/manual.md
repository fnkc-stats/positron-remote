# Как работать с проектом: коротко

Всё делается кнопками на панели **FNKC** (иконка логотипа ДГОИ, на панели действий Positron).

## Один раз: настройка

1. Получите у администратора файл `config.json`, а также отпечатки (fingerprints) ключей сервера и Gitea.
2. Если SSH-ключа у вас нет, создайте его: `ssh-keygen -t ed25519` (на все вопросы — Enter). Отправьте администратору файл `~/.ssh/id_ed25519.pub` и добавьте его же в Gitea: **Settings → SSH / GPG Keys**. Файл без `.pub` никому не отправляйте.
3. Установите Positron той версии, которую назовёт администратор. Установите расширение из последнего выпуска (ссылка не меняется, вход в GitHub не нужен):

   ```sh
   curl -fL https://github.com/fnkc-stats/positron-remote/releases/latest/download/fnkc-projects.vsix -o /tmp/fnkc-projects.vsix
   "/Applications/Positron.app/Contents/Resources/app/bin/code" --install-extension /tmp/fnkc-projects.vsix --force
   ```
   (на Windows: скачайте файл по ссылке и выберите его в Positron: **Extensions → … → Install from VSIX**). Дальше расширение обновляется само: раз в день оно проверяет новый выпуск и предлагает **Update** (вручную: **FNKC Projects: Check for Updates**).
4. Положите `config.json` в `~/.config/fnkc-ctl/config.json`.
5. Загрузите ключ: `ssh-add --apple-use-keychain ~/.ssh/id_ed25519` (macOS) или `ssh-add ~/.ssh/id_ed25519`.
6. На панели FNKC нажмите на список с галочками. Удостоверьтесь, что всё готово к работе. Если что-то не так, выберите строку: команда для исправления скопируется, вставьте её в терминал. Строка **Positron updates** выключает автоматические обновления Positron: образы проектов собраны под одну его версию, и обновляемся мы все вместе.

## Новый проект

В Gitea: **+ → New Repository**, в поле **Template** выберите шаблон с нужной версией R (например `template-r-4.5`) и задайте имя репозитория.

## Открыть проект

1. На панели FNKC нажмите **+**, введите имя репозитория (например `muhina-PI-2026-1`) и нажмите enter.
2. Первое открытие нового окружения на сервере занимает несколько минут, следующие — секунды. Не закрывайте окно, пока проект не откроется.
3. Репозиторий клонируется внутри контейнера. `renv::restore()` выполняется автоматически при запуске контейнера.
4. `container.json` закрепляет только R-окружение проекта, менять его не нужно ни при какой версии Positron. Если к окружению ещё не добавлен сервер вашей версии Positron, Open предложит **Build Environment** — нажмите, дождитесь сборки (несколько минут) и откройте проект из предложенной кнопки. Это нужно один раз для каждого окружения и версии Positron.

На панели проект называется так же, как репозиторий в Gitea.

Уже открывавшийся проект виден на панели под сервером: нажмите на него или на значок ↗ рядом.

## Работа

Работайте в открывшемся окне. Коммитьте и пушьте как обычно, часто. Файлы проекта хранятся на сервере, а не на вашем компьютере.

## Закончить

Нажмите кнопку **■ <проект> (<сервер>)** внизу окна в строке состояния. Файлы сохранятся, контейнер и окно закроются. Остановка не меняет `renv.lock`. После намеренной установки пакетов сначала выполните `fnkc-projects snapshot`, проверьте и закоммитьте изменения. Проект можно остановить и с панели FNKC: кнопка **■** рядом с ним.

Просто закрыть окно — не то же самое: проект продолжит работать на сервере и занимать память.

## Удалить проект

Когда проект больше не нужен на сервере, остановите его и нажмите корзину рядом с ним на панели FNKC. Сначала расширение проверяет, что потеряется:

- если вся работа уже в Gitea (нет незакоммиченных, незапушенных, спрятанных в stash и игнорируемых файлов), оно так и пишет (служебные файлы редактора и системы — `.vscode/`, `.positron/`, `.Rhistory`, `.DS_Store` и т. п. — если они не в git, не считаются работой и удалению не мешают) и перечисляет удаляемые тома;
- если нет — открывает отчёт: каждый файл, папка и коммит, которых нет в Gitea, и удаляемые тома. Можно открыть проект, закоммитить и запушить, или удалить его вместе с этой работой (ещё одно подтверждение).

Удаляются контейнер, тома проекта (папка проекта, настройки Positron, R-пакеты, расширения) и его сеть. Репозиторий в Gitea не меняется: при следующем открытии проект клонируется заново.
