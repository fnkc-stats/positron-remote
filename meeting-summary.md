# Контейнеры и агенты: итоги созвона

Использование контейнеров планируется для создания безопасной и изолированной среды под работу ИИ-агентов.
Это позволит агентам писать аналитические скрипты без риска утечки информации, так как в изолированном
пространстве у них не будет доступа к локальным папкам (например, downloads) и напрямую к расшифрованным
данным. Агент будет работать только в рамках контейнера, собирая необходимый код и отправляя его напрямую
в репозиторий для дальнейшей проверки.

Рабочий процесс планируется разделить на два безопасных этапа пайплайна. Сначала изолированный агент собирает
скрипт (например, Rmd) без доступа к чувствительной информации, после чего система непрерывной интеграции (CI)
в рамках pull request компилирует итоговый HTML-отчет уже с реальными данными. Такой серверный подход защищает
от локальных обрывов связи, а готовые результаты работы можно будет проверять по ссылке из автоматических
уведомлений, например, в Telegram.

Контейнеризация поможет решить проблему воспроизводимости рабочих сред на любых устройствах и снизить
зависимость от единственного рабочего сервера (bus factor). Для организации новой архитектуры
и управления рабочим окружением предполагается:

- использовать Docker для жесткой фиксации всех необходимых пакетов и зависимостей под каждый отдельный проект;
- применять одни и те же базовые контейнеры как для ручной работы аналитиков, так и для запуска ИИ-агентов;
- настроить реестр контейнеров на базе GitHub (или Gitea), а запуск самих агентов перенести в Яндекс.Облако.
